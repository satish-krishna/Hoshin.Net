# Changelog

All notable changes to **Hoshin.Net** are documented in this file.

## [Unreleased]

### Changed
- **Cross-platform packager (`packaging/package.ps1`):** Uses `Join-Path` throughout, runs under `pwsh` on Linux and Windows, reads default version from `Directory.Build.props` (`VersionPrefix`), and stamps `-Version` into the generated Claude Code `plugin.json`.
- **Strict analyzer & complexity build gate:** Enabled `TreatWarningsAsErrors`, `AnalysisLevel=latest-recommended`, `EnforceCodeStyleInBuild`, `.editorconfig`, and `CA1502` (cyclomatic complexity ≤ 15 via `CodeMetricsConfig.txt`); replaced per-call hot-path regexes with `[GeneratedRegex]`.
- **Architecture & SOLID test suite (`tests/Hoshin.Tests/Architecture/`):** Automated checks for rules A1, A2, S2, S3, CA1502, I1, I2, D1–D4, and C3 with a shrinking `baseline.json`.
- **Conventional names workflow (`.github/workflows/conventional.yml`):** Validates PR title, branch name, every commit header, and unique `Task: <id>` trailers from `docs/review/TASKS.md` on `fix/review-findings`.
- **Changed-line coverage gate (`.github/workflows/ci.yml`):** Collects full-suite coverage (including child `dotnet hoshin.dll` black-box processes) with `dotnet-coverage`, enforces ≥ 90% changed-line coverage on `src/**` via `diff-cover`, and uploads the HTML report artifact.
- **Active-run guard & trace scoping (T01):** `hoshin guard` and `hooks.jsonl` tracing now apply strictly to repositories with an active, non-stale `.git/hoshin/run.json` matching the calling session (or its active subagent), stay silent without creating `.git/hoshin/` outside active runs, and log static denials when active.
- **Human-only approval and acceptance (T02):** Generated `SKILL.md` wrappers for `accept` and `done` emit `disable-model-invocation: true`, and `HookOrchestrator` rejects model-sourced `accept`/`done` invocations (`PostToolUse(Skill)` or `SKILL.md` reads) without changing state.
- **Harness config & hoshin state protection (T03):** `GuardTamperingProtection` denies writes to `.claude/settings*.json`, `.claude/hooks/`, `.git/hooks/`, `<git-common-dir>/hoshin`, and shell write commands targeting git/hoshin state tokens; `HookOrchestrator.HandleStop` blocks if `run.json` is deleted mid-run while an unfinished ledger exists.
- **Guard bypass hardening & library HEAD enforcement (T04):** Normalized shell commands (stripping empty quotes and line continuations), extended `GitPrefix` (`--git-dir`, `--work-tree`, `--namespace`, `-C`), blocked inline/configured git aliases and `git commit ... -n`, matched `>`/`>>`/`|` prefixes on protected paths, and enforced `WorkflowHeadGuard` in `EvaluateAndCommitTask` so manual commits outside the workflow fail the attempt without committing.
- **Base-branch build checks (T05):** `BaseBranchChecksReader` loads blocking `build.finish` checks exclusively from the base ref via `git show <base>:...` (combining `.hoshin.json`, `intent/<system>/hooks.json` via `HookConfigService`, and any committed per-change `hooks.jsonc`/`hooks.json`, with a uniform `blocking` default of `true`), preventing working-tree tampering.
- **Change-folder & shell-redirect protection (T06):** Protected the active change folder during `Implement`/`Retry` in both `WorkflowRunner.IsProtectedPath` and `GuardCommand`, and added `ShellWriteTargets` to enforce Red-phase and single-document write locks on shell `>`, `>>`, and `tee` targets.
- **Per-change workflow ledger (T07):** Scoped the workflow ledger to `.git/hoshin/changes/<change>/workflow-ledger.json` via `ChangeLedgerPaths` so task IDs across different changes never collide, with one-time migration of legacy `.git/hoshin/workflow-ledger.json` when `run.json` names a change.
- **Task path isolation & NUL-delimited status parsing (T08):** `WorkingTreeSnapshot` captures pre-issue dirty/untracked file digests and staged-index state on `WorkflowIssued`, parses `git status --porcelain=v1 -z -uall`, refuses attempts when the index had staged changes before issue, excludes unchanged pre-issue files, commits with explicit `-- <paths>` pathspecs, and resets `--mixed` to `startHead` on any failure after staging begins.
- **Serialized task evaluation and commit (T09):** Added `FileLock` and a run-level lock (`.git/hoshin/run.lock`) held across `WorkflowRunner.EvaluateAndCommitTask`, re-reading the live ledger inside the lock to return any existing verdict before touching the working tree, worktree, or git history.
- **Fail-closed YAML migration (T10):** Hardened `YamlToJsoncConverter` and `DocumentMigrator` via `MigrationGuard` to refuse unconsumed lines, anchors/aliases/tags, multi-line quoted scalars, block scalars inside sequences, nested sequences, duplicate keys, leading `---` in `change.yml`, and partial flow collections; fixed quote-aware inline comment stripping (`SplitInlineCommentSafe`); and verified converted JSONC retains every source key before rewriting or deleting `change.yml`.
- **Blank & comment-only JSONC handling (T12):** Fixed `Jsonc.IsBlank` so empty, whitespace-only, and comment-only (`// ...`, `/* ... */`) JSONC inputs return `true` with `value = null` as documented (while unclosed `/*` still fails), allowing comment-only `## Shared decisions` blocks in plans.
- **Token-based `FrontMatterEdit.Set` (T13):** Rewrote `FrontMatterEdit.Set` using `Doc` and `Utf8JsonReader` byte spans so existing string, `null`, number, boolean, array, and object properties are updated in place without duplicate keys, comments are never rewritten, missing keys are inserted before `}` matching existing indentation and trailing-comma style, CRLF/LF line endings are preserved, and writes are atomic (`File.Move`).
- **Hardened `RedClassifier` (T14):** Added `RedKind.CouldNotRun` for exit `126`/`127`, `could not start`, worktree setup failures, and bare/non-target missing modules (`Cannot find module`/`ERR_MODULE_NOT_FOUND`/`TS2307` now count as `MissingSymbol` only for relative or production-path specifiers); added Go, Rust (`E0425`/`E0433`/`E0412` valid vs `error: expected` and other `E0xxx` invalid), and Java (`error: ';' expected`) classification rules.
- **Test-path classification & glob fixes (T15):** Extracted `TestPathClassifier` so `ExtractTestFilesFromArgv` normalizes paths via `Path.GetFullPath`/`Path.GetRelativePath` (without stripping leading dots or accepting paths outside the repo) and accepts only verified test-pattern files or known test suffixes (ignoring `.csproj`/config args), and fixed `**/` glob translation to `(?:.*/)?` so `**/foo` never matches `barfoo`.
- **Working-directory executable resolution (T16):** Added `ProcessExecutable.Resolve` and wired it into both `AllowListedCommandRunner` and `ProcessCommandRunner` so relative `argv[0]` executables containing a path separator resolve against `workingDirectory` instead of the parent process cwd.
- **Proxy, CA, toolchain & push environment allow-lists + publish diagnostics (T17):** Extended `AllowListedCommandRunner.AllowedEnvironmentVariables` with non-secret proxy, CA certificate, and toolchain variables; added a separate push-only allow-list (`SSH_AUTH_SOCK`, `GIT_SSH_COMMAND`, `GIT_ASKPASS`, `GCM_*`) used exclusively by `Publish` (never exposed to task tests); added optional `.hoshin.json` `"env": { "allow": [...] }` support in `MarkerReader` and `WorkflowRepo`; and changed `WorkflowRunner.Publish` to return `WorkflowPublishResult` with git error diagnostics surfaced by `HookOrchestrator`.
- **Reliable `ProcessCommandRunner` timeouts & cancellation (T18):** Rewrote `ProcessCommandRunner.RunAsync` to stream stdin on a background task, read stdout/stderr concurrently into a thread-safe `StreamCollector`, await `WaitForExitAsync` with linked timeout + caller `CancellationToken`, kill the entire process tree on timeout/cancellation, and cap post-exit pipe draining at 2 seconds so background grandchildren cannot hold calls open.
- **Corrupt-ledger protection & locked `LedgerStore.Update` (T19):** `LedgerStore.Read` now throws `CouldNotRunException` naming the file instead of swallowing corrupt JSON and wiping history, and added `LedgerStore.Update` (backed by shared `FileLock` and unique-temp atomic `File.Move`), routing `RedRecorder`, `EventRunner`, `BaselineApprovals`, and `GateCommand` through it.
- **`SpecReader` fence & `Scenario Template` fixes (T20):** Updated `SpecReader.FindBlock` to select the first top-level `gherkin` fence from `Doc.Fences` (ignoring nested `gherkin` snippets inside outer fenced examples) and detected outlines by `Examples` presence or `Scenario Outline`/`Scenario Template` keywords.
- **Session-scoped hook & guard isolation (T22):** Extracted shared `HookSessionScope.IsRunSession` so `HookOrchestrator` (`HandleStart`, `HandleResult`, `HandleSubagentStop`, `HandleStop`) and `GuardCommand` act strictly for the owning run session or its registered active subagent, treating missing `session_id` and unrelated sessions/agents as outside the run.
- **Non-intrusive `setup`/`context` hooks (T23):** Moved the `setup`/`context` early return in `HookOrchestrator.HandleStart` above active-run checks, `ReadState`, `WriteRunMarker`, `ResetStops`, and step writes so `setup`/`context` work in repositories without a change plan and never take over an active run.
- **Dispatched subagent nonce verification (T24):** Embedded a per-attempt dispatch nonce (`<!-- hoshin:<task>:attempt-<n>:<8 hex> -->`) in `CurrentStep.DispatchNonce` and `HookInstructions.For`, and updated `HookOrchestrator.HandleResult` to judge or register only subagents whose prompt contains the active nonce (ignoring Explore/research subagents without burning attempts).
- **Async verdict & `NeedsApproval` reporting (T25):** `HookOrchestrator.HandleSubagentStop` now queues the verdict report into `.git/hoshin/pending-report.txt` under the run lock, and `HandleStop` drains and prepends it on the parent's next Stop, reporting `NeedsApproval` or `Done` once before allowing the following Stop cleanly.
- **Scoped stop counters & continuation/question handling (T26):** Extracted run-locked `StopCounterStore` with separate per-scope counters (`build`, `write-<doc>`, `review`, `fix`), resetting consecutive block counts when `ContinuationActive` (`stop_hook_active`) is `false`, and letting `WriteDocument` yield cleanly when the assistant's last message ends with a question.
- **Unicode-safe middle truncation for injected hook text (T27):** Added `TextTruncator` operating on `StringInfo` text-element boundaries with `[… N characters omitted …]` markers and assembled report/header, middle-truncated prompt body, and closing `END SUBAGENT PROMPT>>>` marker in one place inside `HookInstructions.For` so closing markers and surrogate pairs are never cut.
- **Configurable timeouts & attempt cap (T28):** Added optional per-task `timeout` (seconds) to `plan-task.schema.json`, `read-result.schema.json`, `PlanReader`, and `WorkflowTask`, plus `.hoshin.json` `build: { testTimeoutSeconds, checkTimeoutSeconds, maxAttempts }` read via `MarkerBuildSettings` into `WorkflowPlan` and honored by `WorkflowEngine.Next` and `WorkflowRunner`.
- **Marker `testPatterns` validation (T29):** Accepted optional `testPatterns` (array of non-empty glob strings) in `MarkerReader.MarkerProblems` so `hoshin check .hoshin.json` aligns with `MarkerBuildSettings` and `DESIGN.md §4`.
- **System context discovery in authoring briefs (T30):** Updated `WorkflowBriefs.Intent` (plus `Spec` and `Plan`) to resolve the real system name from `intent/<system>/<change>/`, list `intent/<system>/context/*.md` context files, and keep the `.hoshin/context*.md` fallback.
- **Review gate, `change/<change>` branch default, and PR publishing (T31 / D4):** Defaulted `WorkflowPlan.EffectiveBranch` to `change/<change>`, computed `CodeHead` in `WorkflowRepo` (excluding `<change>/build/review.md`) so checks/reviews/approvals stay keyed to code head across review commits, moved the `ReviewDocument` gate into `WorkflowEngine.Next` (blocking high findings and removing `HookOrchestrator`'s direct `ReviewDocument` construction), defaulted `WorkflowRunner.Publish` to push to the branch's upstream remote (fallback `origin`) and open/reuse a PR via `IPullRequestClient` with full error reporting.
- **Tasks without testable behavior (`test: null`, T41 / D5):** Made `WorkflowTask.Test` nullable, allowed `"test": null` in `plan-task.schema.json` and `WorkflowRepo.ReadPlan`, extracted `ITaskVerdictPolicy` (`RedGreenPolicy` and `NoTestPolicy`), updated `WorkflowBriefs.Implement` and `GuardStepEvaluator` for no-test tasks, and removed `CA1502:WorkflowRunner.cs#EvaluateAndCommitTask` from the architecture baseline.
- **`Hoshin.Migration` assembly backed by YamlDotNet (T11 / D3):** Extracted YAML-to-JSONC migration (`YamlToJsoncConverter`, `IYamlToJsoncConverter`, `DocumentMigrator`) into a dedicated `src/Hoshin.Migration` assembly referencing `YamlDotNet 16.3.0` (referenced only by `Hoshin.Cli`, keeping `Hoshin.Workflow` strictly `Markdig` + `Gherkin`), preserving key order, scanner-exposed comments, and quoted all-digit commit hashes; verified against all 34 differential YAML samples (`YamlDifferentialTests`) and shrank the architecture baseline by 26 entries (418 → 392).

## [2.0.0] - 2026-11-21

### Breaking Changes (`!`)
- **Retired `tools/hoshin.ts` in favor of `dotnet hoshin.dll` (.NET 10):** All CLI commands, lifecycle events, and hooks now run through the portable .NET 10 build (`hoshin.dll`, `Hoshin.Workflow.dll`, `Markdig.dll`, `Gherkin.dll`) with `RollForward=Major`.
- **JSONC replaces YAML in all Hoshin documents and records:**
  - Front matter must be a fenced ```` ```jsonc ```` block starting on line 1 (bare line-1 JSONC written during authoring is auto-wrapped before commit; YAML `---` front matter is refused with migration guidance).
  - Record blocks in `plan.md`, `build/*.md`, and `build/review.md` use ```` ```jsonc ````.
  - `change.yml` is replaced by `change.jsonc`.
  - Layout 1 readers are removed from `Hoshin.Workflow`; migrate legacy repositories with `hoshin migrate`.
- **Kata Workbench migration:** See [docs/KATA_MIGRATION.md](docs/KATA_MIGRATION.md) and [CLIENTS.md](CLIENTS.md).

### Added
- **`Hoshin.Workflow` NuGet package (`2.0.0`):** Minimal dependencies (`Markdig` + `Gherkin` only), zero harness references, embedded JSON schemas, workspace templates, and all 11 harness-neutral role/skill procedures.
- **Document & record migration (`hoshin migrate`):** Zero-dependency YAML-to-JSONC converter and idempotent migrator for Layout 1 & Layout 2 Markdown documents and `change.yml` → `change.jsonc`, supporting `--dry-run`, `--write`, and `--documents`.
- **Pure workflow state machine (`WorkflowEngine.Next`) & two-phase Red/Green runner:** Full lifecycle (`WriteIntent` → `AwaitAccept(intent)` → `WriteSpec` → `AwaitAccept(spec)` → `WritePlan` → `AwaitAccept(plan)` → `Implement`/`Retry` → `RunChecks` → `Review` → `NeedsApproval` → `Publish` → `Done`), cached detached worktree Red verification with strongly-typed missing-symbol classification (`CS0246`, `CS0103`, `CS1061`, `TS2304`, ESM missing exports), atomic test-then-implementation commits, and allow-listed secret-free command execution.
- **First-class dual-harness hooks (`hoshin hook` + `hoshin guard`):** Native payload normalization and response formatting for both **Claude Code** and **Google Antigravity**, supporting foreground and async background subagents, session-aware fast-path guarding, and authoring/review/fix Stop gates.
- **Dual-bundle release packager (`packaging/package.ps1`):** Produces `artifacts/portable/` (`lib/` + `skills/`), `artifacts/nuget/Hoshin.Workflow.2.0.0.nupkg`, `artifacts/claude-code/` (`.claude-plugin/`), and `artifacts/antigravity/.agents/`.
